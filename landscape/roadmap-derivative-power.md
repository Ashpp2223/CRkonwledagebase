# 衍生战斗力优先路线图

目标不是把所有仓库集成到一起，而是逐项提高**跨项目复用效率**。优先次序兼顾通用程度、验证难度、现有材料质量和下游收益。

| 先后 | 交付物 | 来源技术 | 为什么有杠杆 | 现实限制 |
| --- | --- | --- | --- | --- |
| P0 | **可复制状态的能力对照和测试契约** | FirstLight 原生快照、itzik 深拷贝、RoyaleSim save/load、Ashpp 动作日志 | 回放、分支、MCTS、A/B 搜索共用核心概念 | 自建模拟器与原生引擎状态不同构 |
| P0 | **数据/动作/时间单位对照表** | FirstLight ActionV1、Jason Play、RoyaleSim 输入、itzik 空间动作 | 所有训练和回放跨项目转换的基础 | 每套坐标、tick、手牌槽可能不同 |
| P0 | **机制保真评估范式与最小场景** | Hasty、RoyaleSim、larkindaniel | 可把单个发现转为全部项目可复用的验证用例 | 需合法真实对局基准，不能虚构通过率 |
| P1 | **回放→观测→训练数据版本标识规范** | FirstLight、Jason、ClashAI | 可让训练模型与研究者共享可追溯样本定义 | 视频/回放权属与隐藏信息泄漏 |
| P1 | **CV 事件 schema + 对齐验收** | KataCR、BuildABot、ClashAI | 将视觉检测扩展至解说、回放与 AI | 现实画面变化、模型域偏移与延迟 |
| P1 | **资源/卡牌表版本清单** | SC Downloader、sc_extract、RoyaleAPI Data | 提供重复构建和数值差分的基础 | 客户端资源版权、旧表误用 |
| P2 | **设备 Agent 调度与失败恢复模式** | ClashAI、Claude Royale、Tencent Harness | 降低观察/决策/执行三段耦合 | 账号与服务条款边界；优先离线 |
| P2 | **可检索研究问答/自动状态检查** | 既有 Markdown/YAML，中台源码审计记录 | AI 查询可输出带证据的能力选型 | 先验证静态目录，再考虑 RAG |

**本次已落实**：收录高杠杆项目、扩充能力关联、记录衍生技术组合与排除原因。未落实：P0 的第三方原生设备实验、二进制适配层、官方游戏各版本的大样本校准，这些都不能仅靠文档宣称完成。

## 下一项具有最高性价比的执行任务

选定**相同的短对局动作序列**，分别以原生环境和两套独立模拟器重放，记录：

1. 时间基与坐标转换（包含单位、方向、手牌、卡牌 ID）。
2. 每个动作的合法性、是否执行及执行 Tick。
3. 指定战斗对象的事件序列、位置、生命值、攻击时序。
4. 相同 seed 的重复结果与完整内部可见程度。
5. 若分叉，在两条动作后缀之间验证状态隔离。

交付一份能够被后来者引用的 *conformance fixture*，其价值大于继续增加二十张只含 README 的项目卡。
