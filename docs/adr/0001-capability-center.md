# ADR-0001：采用能力优先的技术文档中台

**状态**：Accepted（仅对本仓库信息架构生效）  
**日期**：2026-10-13

## 问题

项目目录优先的百科能回答“谁做了什么”，但难以回答“我需要某项技术，已有方案能不能复用”。不同项目使用不同版本、运行环境与许可，不能强行拼成统一代码框架。

## 决策

- 以 `capabilities/` 作为首要检索入口。
- `registry/implementations.yaml` 管理项目与能力的关联和证据，并单独评级。
- 保留项目卡与研究专题、历史链接；不复制上游代码。
- 将 `contracts/` 全部显式标为 Draft。
- 仅在明确经过实测、许可及版本审查时提升复用等级。

## 取舍

收益：按任务发现能力、避免“作者 README = 可用 SDK”的误解、方便成员独立维护。代价：需维护实现矩阵与证据元数据，并在上游变化后复核。

## 暂不做

公共运行时、统一原生二进制、自动远程复用、全文爬取、未经授权的游戏资源镜像、复杂搜索后端。
