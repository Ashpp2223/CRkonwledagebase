# 复用成熟度、证据与授权

## 三条独立的判断轴

1. **复用成熟度** `R0...R4`：能力在具体项目中的可复用准备程度；按“项目×能力”登记，而不是给整个项目一张总分。
2. **证据等级** `unknown / author-documented / source-inspected / reproduced`：当前条目依据；作者报告的成功不能升级为我们的“复现”。
3. **集成与法律门槛**：运行平台、游戏版本、外部依赖、源码许可证与游戏素材权利需要单独核对。

| 等级 | 描述 | 最低可检查材料 |
| --- | --- | --- |
| R0 | 研究线索/旧实现或待确认线索 | 来源和待验证问题 |
| R1 | 已有可引用的实现说明/技术知识 | 作者文档或研究记录，清晰边界和来源 |
| R2 | 可定位的源码实现经过针对该能力的审查 | 固定提交、核心入口、接口/条件的源码核查记录 |
| R3 | 在**指定环境**已完成可复现的第三方集成测试 | 环境版本、许可证结论、接入步骤、测试日志与结果 |
| R4 | 在 R3 基础上有明确版本支持、维护责任与回归流程 | 维护责任、发布/兼容计划、已运行 CI |

R 等级不表示性能、准确度或安全性的连续分数。R3 不代表“任意平台都可使用”。

## 登记规则

- 只阅读 README：最多 R1；即使 README 声称测试通过，也只能记 `author-documented`。
- 看到源码路径不等于已经审核；必须记录固定 SHA、所检查的关键代码及理由才可到 R2。
- API 具有 `reset/step` 不等于支持任意历史状态克隆。
- 项目若在特定版本失效，该版本对应的能力至少要标明失效状态；R0 可以表示暂不提供可用接入。
- 未显式授权的代码不得默认复制；MIT/Apache 也不自动授权第三方游戏素材。
- 重大更新或证据过时，应降级或标记未复核。

当前 `registry/implementations.yaml` 的初始条目几乎全部 R1/author-documented。它不是已验证的统一组件商店。
